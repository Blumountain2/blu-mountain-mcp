## 1. REST client foundation

- [x] 1.1 Fetch the Public App's access token from `auth.vault` (not `auth.mcp_vault`) and call `api.hubapi.com` via `httpx.AsyncClient` with `Authorization: Bearer {token}`, handling `429` without letting it crash a caller. Implemented differently than originally sketched: no single `_rest_request(hub_id, method, path, params)` helper — instead `_client_for_hub()`/`_headers_for()` resolve the token once per pull and `_paginate()` centralizes the GET+pagination path; a 429 raises `HubSpotRateLimited` internally, which every public method's own try/except turns into `{"error": "pull_failed"}` for its caller, same net effect as "logging and returning a failure marker rather than raising" one level up.
- [x] 1.2 Hand-enumerated REST endpoint constants/paths per family (CRM objects via `CRM_OBJECT_REST_SLUGS`, CRM properties, owners, settings/account-info, marketing emails, marketing campaigns, CMS pages, lists) — no dynamic endpoint construction from caller input beyond a validated object-type name or a defensively-filtered property name.
